# BMPReader

Консольная программа на C++20 для чтения BMP-заголовка и вывода RGB-значений угловых пикселей.

## Возможности
- Поддержка BMP 16, 24 и 32 бита.
- Прямое чтение 54-байтового стандартного заголовка в одну упакованную структуру `BMPHeader`.
- Работа с изображениями с нижним и верхним началом строк.
- Поддержка 16-битных BI_RGB (RGB 5:5:5) и BI_BITFIELDS / BI_ALPHABITFIELDS.
- Проверка заголовка, формата, масок и границ чтения пикселей.
- Обработка ошибок через собственную иерархию исключений.

## ООП
- Инкапсуляция: состояние `BMP` закрыто в `private`.
- Наследование: `BMP` наследуется от абстрактного `Image`.
- Полиморфизм: методы `Image` виртуальные; в `main.cpp` объект используется через `std::unique_ptr<Image>`.

## Сборка
Требуются CMake 3.28+, компилятор с поддержкой C++20 Modules и Ninja (или другая поддерживаемая генератором система).

```bash
cmake -S . -B build -G Ninja
cmake --build build
```

## Запуск
```bash
./build/bmp_reader lena.bmp
```
Если аргумент не указан, программа ищет `lena.bmp` в текущей рабочей папке.

## Как устроено чтение заголовка
В `bmp.cppm` объявлена одна структура `BMPHeader`, содержащая поля BITMAPFILEHEADER и BITMAPINFOHEADER. Благодаря `#pragma pack(push, 1)` её размер равен 54 байтам. `open()` читает эти 54 байта одним `read()` непосредственно в объект структуры.

Маски не являются отдельной структурой: они нужны только для декодирования 16-битных BMP с BI_BITFIELDS / BI_ALPHABITFIELDS и хранятся в массиве из трёх `unsigned int` внутри `BMP`. Для обычного 16-битного BI_RGB используются стандартные маски RGB 5:5:5. Для 24- и 32-битных BI_RGB маски не нужны.

## Типы данных
Используются только встроенные типы C++ (`unsigned char`, `unsigned short`, `int`, `unsigned int`, `long long`, `unsigned long long`) без `<cstdint>`. Размеры `short` = 2 байта и `int` = 4 байта, от которых зависит раскладка `BMPHeader`, проверяются через `static_assert`.

Прямое чтение структуры отражает little-endian разметку BMP и рассчитано на little-endian платформы (обычные x86/x64).
